# Candidate:validate an immutable business batch once

This isolated candidate removes one redundant `new BusinessBatch(batch.commands())` from the V3 operation encoder. It is not deployed or measured as an optimization. The parent-only JFR diagnostic identified repeated canonical business encoding and buffer growth among network-owner CPU samples;that observation motivates testing this change,not a unique bottleneck claim.

The public `BusinessBatch` canonical constructor still validates count,logical identities,unique account/producer pairs,UTF-8,nested bytes and complete request size before making an immutable defensive list. `MatchingEngine.Command` is sealed to the Deposit/Place/Cancel records,whose fields are primitives,Strings and enums. Encoding still canonically encodes every nested command. Decoding still validates nested bytes,constructs a fully validated batch and compares the entire canonical outer encoding. No wire format,logical identity,retention,durability,reply or permission rule changes. No new trusted-wire bypass or shared mutable cache is introduced.

Actual local Mac forced validation passes39 existing wire,adapter,owner,read-bank and transport tests with zero failure/error/skip.
