# First actual PostgreSQL-only probe: startup and stop passed, SQL audit failed

The 18 frozen stage files were SHA-verified on the existing CPU. All 33 Python guards and the Java payload self-test (2 valid / 6 malformed cases) passed there before startup. The original Zonky PostgreSQL18.6 server then started the original physical clone, bound only127.0.0.1:15432 and reported ready. No initdb, new database, schema initializer, projector, event ACK or business generator was invoked.

The one JDBC inspection failed its first settings assertion. Actual transaction_read_only was on, isolation was repeatable read, and fsync/synchronous_commit/version/path were correct; session default_transaction_read_only was off. Consequently no ledger audit or PG-to-Aeron correspondence passed in this attempt. The unchanged partial inspection, stderr, PostgreSQL log, source, JARs and all ownership/control receipts are retained in the raw archive. `first-outcome.json` exposes the short settings failure for review.

The pinned [PgJDBC42.7.10 PgConnection source](https://raw.githubusercontent.com/pgjdbc/pgjdbc/REL42.7.10/pgjdbc/src/main/java/org/postgresql/jdbc/PgConnection.java) explains the mismatch: with readOnlyMode=always, switching autocommit off explicitly resets the session default to read-write, while subsequent transactions can still be read-only. A separately versioned inspector using transaction mode will preserve the startup default and retain both read-only assertions. This failed result is not rewritten or silently accepted.
