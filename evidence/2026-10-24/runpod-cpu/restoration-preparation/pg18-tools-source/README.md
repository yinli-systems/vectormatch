This directory prepares exact official PostgreSQL 18.6 source and a draft native build for the missing pg_controldata/pg_config tools. No source compilation, SSH, cloud command, PGDATA inspection, PostgreSQL server startup or initdb was performed by this preparation. The CLI defaults to a plan and does not build unless --execute is supplied.

The official source index https://ftp.postgresql.org/pub/source/v18.6/ lists postgresql-18.6.tar.bz2 and its .sha256. Both were downloaded directly from that primary HTTPS location (HTTP 200, no host substitution). The 22,632,314-byte archive SHA-256 matches the published checksum:
555610c24d53e4316da5b7d3fc25c279d96856d5e0e23ee308c328c5fa881d9f
The exact official .sha256 file, commands, URLs, times and results are preserved. No minor/major substitution was made.

SOURCE_INVENTORY.json records 7,944 archive members, 7,284 regular files, 141,525,674 regular-file bytes and no symbolic/hard links. configure.ac declares exact version 18.6; src/include/catalog/pg_control.h declares PG_CONTROL_VERSION 1800. Relevant leaf Makefile and configuration-input hashes are recorded. The leaf make targets depend on generated headers plus src/port and src/common libraries; those necessary prerequisites are allowed, while no server, pg_ctl or initdb target is requested. A completed build explicitly rejects finding those three executables in the build tree.

Dependencies already present on the target must include a C99 compiler (cc), GNU make >=3.81, Perl >=5.14, Bison >=2.3, and Flex, plus ordinary Unix shell/build utilities. The script reports missing dependencies and stops; it contains no apt, package upgrade or download step. Configure disables ICU, OpenSSL, Readline, zlib, optional procedural languages, LLVM, LZ4/Zstd and NLS for this tool-only build, so their development packages are not required. These choices describe this new tool build; they are not changes to the original Zonky server.

The primary upstream requirements and VPATH/configure documentation are https://www.postgresql.org/docs/18/install-requirements.html and https://www.postgresql.org/docs/18/install-make.html. The tools are documented at https://www.postgresql.org/docs/18/app-pgcontroldata.html and https://www.postgresql.org/docs/18/app-pgconfig.html. pg_controldata is intended to read cluster control information; this build script only runs its --version, with no data-directory argument. A later explicit read-only PGDATA check remains a separate action.

build-pg18-tools.py is a Python 3.8-compatible local-input-only script. Execute requires explicit idle confirmation, Linux x86_64, an absolute new child directory of /opt/vectormatch-cpu/tool-builds, no symlink ancestor, the local overlay filesystem and at least 3 GiB free before and after extraction. It rejects any observed VectorMatch/JMH JVM, does not print full process arguments/environments, and checks again before each compilation. The source SHA and safe bounded file-only tar inventory are checked before configure. The caller remains responsible for exclusive scheduling so a benchmark cannot be started concurrently after the checks.

It uses an out-of-tree build, a separate install prefix, a restricted build environment and two serial make commands with literal -j2. Configure timeout is 180 seconds; each make timeout is 600 seconds; version checks are bounded at 10 seconds. Each command owns a new process session, writes a separate log and preserves status/hash evidence. CLI SIGINT/SIGTERM sets a cancellation flag; command waits check it at most once per second, stop the owned unreaped-child process group and retain a failed receipt. Timeout/KeyboardInterrupt guards exercise the same failure path. A normal leader exit with remaining group members is recorded as unproven cleanup and fails closed; no unidentified group is signaled. SIGKILL/machine loss cannot provide an orderly cleanup guarantee. No failed directory is automatically deleted/retried and no following build step runs after failure.

The requested data-format defaults are fixed at 8 KiB database blocks, 8 KiB WAL blocks and 1 GiB relation segments. The generated header must show PG_VERSION 18.6, PG_VERSION_NUM 180006, BLCKSZ/XLOG_BLCKSZ 8192, RELSEG_SIZE 131072, 8-byte pointers and MAXIMUM_ALIGNOF 8. These checks establish this tool build's declared format, not successful reading of the saved native PGDATA. The actual native cluster control version/CRC/system identifier/catalog/shutdown state/block sizes/locale must still be checked separately; do not run initdb to hide a mismatch.

The outputs, if a future build passes, are <work-dir>/install/bin/pg_controldata and pg_config. Only their --version and this pg_config --configure are executed. pg_config describes THIS tool build and prefix, not the original portable Zonky server, its original configure flags or binary compatibility. The original Zonky server and native state are never replaced by this script. No full server is installed.

Example after root uploads this directory as /workspace/vectormatch-restore/pg18-tools-source and all CPU benchmark processes have stopped:

    python3 /workspace/vectormatch-restore/pg18-tools-source/build-pg18-tools.py \
      --source /workspace/vectormatch-restore/pg18-tools-source/postgresql-18.6.tar.bz2 \
      --work-dir /opt/vectormatch-cpu/tool-builds/pg18-tools-18.6-r1

This command is a dry run. The separately scheduled execution uses the same arguments plus --execute --benchmark-idle-confirmed. Source may be read from the declared FUSE archive, while extraction/compilation/output stay on overlay; an existing work directory always fails. The future BUILD_PLAN.json, BUILD_RESULT.json and logs stay under that unique work directory.

DRAFT_PLAN.json is the actual successful local dry-run output. OFFLINE_VALIDATION.json and offline-guards.log record 20 passing pure offline tests and Python 3.8 AST checks; compilers and real child processes are mocked in command-cleanup tests. Initial read-only peer review found no target/path/VPATH/j2/filesystem issue and identified an interrupt-cleanup gap. That gap was fixed and covered by the final tests; the peer did not re-read the final source, so final root review remains required. No actual Linux compile or output compatibility is claimed.
