## Budgets and proof limits

Initial admission requires3GiB filesystem free and8GiB of cgroup/system memory headroom. Runtime monitoring samples at250ms: free space must remain≥2.5GiB, owned allocated growth≤512MiB and each process log≤4MiB. Three1GiB node heaps plus128MiB probe heap are explicit; native/mapped/RSS consumption is not a hard heap-derived bound. Disk-growth/log limits are sampled admission checks, not filesystem quotas. Kernel-blocked I/O, external controller death or shutdown-hook behavior cannot be given a hard real-time bound.

An original snapshot contains old client-session response addresses; the loopback peer configuration does not rewrite those session records. Preserve them and observe errors rather than altering the snapshot or deleting a session.

Queries and client sessions may append consensus/session metadata and change the native working clone. Application business state/outbox must remain unchanged across the probe, and stopped PG bytes must remain unchanged. Before-state originals remain immutable in the archived source backups.

This proves only successful three-process original-clone startup and one leader's tail-aware canonical/outbox observation, if actual execution later succeeds. Three current replica canonical states require the separately planned maintenance checkpoint plus manifest-bound offline reader; no maintenance toggle is included. Full historical event correspondence, external durability, capacity, p99, independent hosts and all100M targets remain outside this lifecycle controller.
