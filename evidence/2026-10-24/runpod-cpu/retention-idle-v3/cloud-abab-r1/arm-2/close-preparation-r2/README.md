# Manual CPU idle closure inspection r2

Supports one explicit arm 2, 3 or 4. Arm1 r1 remains frozen and unchanged. Requires the actual controller PID, Linux startTicks, argv SHA and immediate preceding independently collected arm gate SHA. The selected park is fixed by arm order 1ms, 100us, 1ms, 100us.

Thirteen local pure mocked guards passed. No remote probe, SSH, JVM, signals, cleanup or benchmark was executed for this preparation. Exact test inputs, command, interpreter, stdout and stderr are retained in guards-r1.

The inspector reads only launch registration and process identity while the controller is active. After strict PID absence it checks the matching ready release, immutable controller source, immediate prior gate, stopped parent plus three exact node identities, full successful control receipts, protected original native57/PG989 values and archive metadata. It never reads raw CSV, archive payload or native files, and does not replace independent collection/audit. A reused PID or zombie is not strict absence.

Arm2's caller-supplied actual identity and exact argument vector are recorded in PREREGISTRATION.json. For arm3/4, the root coordinator must supply those arms' actual launch identity and exact immediate preceding collection gate SHA. One invocation only; no loop or automatic resubmission. The tool does not authorize another arm.

Warnings remain qualified post-checkpoint log-order observations; their wall-time relation to SIGTERM and harmlessness are not claimed. A successful closure control receipt is not a capacity or performance claim.
