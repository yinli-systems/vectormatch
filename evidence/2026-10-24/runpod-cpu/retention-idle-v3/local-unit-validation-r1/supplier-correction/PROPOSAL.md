# Bounded supplier-consumption correction

The native-r1 failure is preserved with its original source/JARs and closed byte archive. The old one-per-logical-role assumption was wrong. On the exact SHARED Archive, enabled control-channel, non-invoker consensus path, each selected agent supplier is consumed twice. Every successful call must return a fresh independent backoff object; its tuple remains unchanged except for the selected maximum requested park.

Archive consumption 1 is an idle object passed to the control-subscription registration retry helper. A retry reuses that object; it does not call the factory again. Consumption 2 is passed to Archive's shared AgentRunner. Consensus consumption 1 is cached by ConsensusModuleAgent for internal waits; consumption 2 is passed to ConsensusModule's AgentRunner. Service consumption 1 is cached by ClusteredServiceAgent; consumption 2 is passed to the container's AgentRunner. Driver creation remains one explicit shared-driver object. Thus there are seven creations per node and one owner-driver creation: twenty-two total for this local three-node workload, associated with thirteen selected logical roles. These counts are not counts of live threads or actual sleep operations.

The fix records role, per-role consumption ordinal, distinct instance ordinal, actual strategy class/description/full configured tuple and source-derived intended use for every creation. A small bounded construction-time stack trace records the actual caller chain without asserting private AgentRunner field readback. The runtime proof will separate the driver's directly observed context object from source-order factory association; an unused retry strategy is not labelled an extra running agent. No extra supplier getter is invoked to make an observation. Exact counts are required at post-launch attestation; a third agent consumption, second driver creation, unknown role or unsupported threading/control-channel scope fails closed. Absent opt-in preserves legacy paths.

Pure guards will exercise both fresh consumptions for each selected agent, disjoint mutable state across every instance, third-call refusal without new allocation, exact-count missing-consumption rejection, actual configured tuples, unsupported-scope rejection and unchanged legacy defaults. The complete affected non-native166 selection and forced distribution will be rerun once on new frozen source, with its own immutable attempt. A new direct installed-JAR native attempt follows only that successful validation and peer review. Old native-r1 is never reused or overwritten.
