This method is registered before reading the new closed CPU long-run raw data. Its pure guards use synthetic events only. It reads one exact release, source configuration, summary, all 33792 arrival rows and twelve verified cycle receipts after checking the actual root full-collection review and strict full raw audit. Every data file must match that raw audit's original input bytes/SHA. It rejects a local functional diagnostic, invalid scheduler, unknown, notSent, rejected, replayed, duplicate or missing original arrival.

All calculations use integer timestamps from the same JVM monotonic clock. CSV offsets are relative to `scheduledOriginMonotonicNs`; cycle timestamps are converted using that exact origin. At a boundary `t`, an event is included when its timestamp is `<=t`. Adjacent boundary intervals are `(previousEnd,currentEnd]`.

At every cycle start and end the analyzer independently counts scheduled-due, released, dispatched, positively offered and replied originals. The four disjoint due states are scheduled-not-released, released-not-dispatched, dispatched-awaiting-reply and known accepted. Their sum must equal scheduled-due. The dispatched state is also split into not-yet-positively-offered and positively-offered-awaiting-reply. Released-not-fully-confirmed equals released-not-dispatched plus dispatched-awaiting-reply; it is not an independently observed owner queue.

Cuts 2 through 11 are the ten equivalent cuts: each contains 3072 taker commands and 6144 events. Cut 1 includes the three setup commands (3069 takers); cut 12 has three takers. All twelve receipts and the final 33795-command/67587-event prefix must close. Every cut starts after definite business reply closure; its known accepted count stays unchanged throughout maintenance. Equivalent cut-end drift uses only adjacent pairs 2→3 through 10→11. It reports exact arrival/release/dispatch/reply counts, rates and the corresponding conservation identity for each backlog delta. Maintenance arrival growth and the preceding end-to-end interval are distinct observations.

Latency is unconditional within each explicitly named cohort because all planned originals must ultimately confirm. The exact command-cut cohort maps final accepted command sequence to the cut. A second cohort selects arrivals scheduled between adjacent cut ends; its size is variable and is not the 3072-command cut size. Global latency covers all 33792 planned arrivals. Each cohort reports scheduled-to-reply, scheduled-to-dispatch, scheduled-to-release, release-to-dispatch, dispatch-to-first-positive-return and first-positive-return-to-reply quantiles. Quantiles are nearest-rank and must never be added to reconstruct another percentile.

No automatic stable/unstable label, hard real-time guarantee, infinite-capacity extrapolation or owner-queue identity is emitted. The result describes this finite 67.584-second offered source plus drain on one host. Every input, source and output is pinned; output directories are exclusive. New failed executions must remain preserved and must not overwrite an earlier attempt.
