# Correlating original requests with recording and commit gates

The preceding empty-service control and two negative ABAB experiments leave replication/storage/scheduling as priorities. This protocol adds exact request-to-log-position attribution before selecting a performance change. It does not infer a cause by subtracting marginal percentiles.

The diagnostic uses pinned Aeron 1.53.3 source with hash-checked, additive hooks in `LogPublisher`, `ConsensusModuleAgent`, `RecordingWriter` and `RecordingSession`. A separate overlay JAR precedes the original Aeron JAR only in this explicit experiment. The production dependency remains unchanged. Raw source hashes, the complete patch and actual class-origin logs bind the running hooks to their source. Archive, catalog and consensus sync levels stay at 2.

Each original `(cluster session, correlation)` maps to the successful log publication's end position and log session. Each replica's containing recording block is selected by its exact `(startPosition, endPosition]` interval. Record local write and file-force intervals, recording-position publication, follower position acknowledgements received by the leader, leader commit publication, service callback, egress offer, client callback and final source confirmation. No nearest-timestamp matching is allowed. Every original must join; missing stages, clock-domain mismatches, tape overflow or canonical state disagreement invalidate attribution.

All four JVMs use a small JNI clock calling Linux `clock_gettime(CLOCK_MONOTONIC)`. Boot ID and time namespace must match. The source's absolute arrival clock and original samples use this same native clock, including when tracing is disabled. Wall-clock timestamps are only used for existing coarse JFR/CPU windows. Do not subtract unrelated JVM clock origins or wall-clock timestamps to obtain request stage durations.

Per-thread bounded primitive tapes allocate before their first event and serialize only on shutdown. The fixed IOC setup/warmup precedes measurement. Trace OFF and ON use the same instrumented artifact, native clock, G1, heap, CPU sets, leader, 1 ms idle limit, overlay driver layout, outbox bounds and sync2. Run two functional qualifications at 10/s for 2 seconds, then OFF/ON/OFF/ON at 100/s for 30 seconds. All original arms, including failed measurements, are archived. These controls assess observer effects; they are not a performance optimization claim. Any material observer effect must accompany the attribution results.

For each complete original, partition planned-to-confirmed latency into source schedule lateness, source queue/offer preparation, ingress delivery, ingress processing, durability/quorum gate, commit polling after that gate, service dispatch, business-to-egress, reply delivery and client finalization. The gate is the later of local recording-position publication and the first qualifying follower acknowledgement. Its critical branch is further split into archive arrival/polling, file write, trace bookkeeping before force, file force, recording publication and acknowledgement delivery. The partitions must sum exactly to that original's full latency.

Recording and commit counter updates have measured visibility intervals. Additive stage anchors use the beginning of these intervals and preserve both ends, rather than asserting a nanosecond-exact instant for another thread's observation. File-force duration includes OS descheduling; archive arrival/polling and acknowledgement delivery combine transport and scheduling. This does not certify physical media latency or power-loss durability.

Only after the original trace controls close may an optimization hypothesis be selected and frozen in a separate protocol. Every implementation change then receives a new qualified artifact and same-configuration ABAB controls; preserve the full decision rule and negative results. Use the existing prepaid CPU only. No new resources, weaker acknowledgement durability or production trading are part of this experiment.
