# Disposable driver buffers versus durable archive placement

The first path decomposition finds tens of milliseconds of scheduled-to-reply tail even with no business logic, while worker callbacks are much shorter and replica file-force calls show long stalls. Three replicas share one overlay filesystem. This motivates a distinct layout experiment; it does not prove the shared filesystem is the only cause.

[Aeron's official performance guide](https://github.com/aeron-io/aeron/wiki/Performance-Testing) recommends a RAM disk for the Aeron directory. In the pinned [1.53.3 RecordingWriter](https://github.com/aeron-io/aeron/blob/1.53.3/aeron-archive/src/main/java/io/aeron/archive/RecordingWriter.java), sync level 2 forces both content and metadata for each recorded block. **Keep that archive/consensus durability configuration unchanged.** Only disposable media-driver communication buffers may move to tmpfs. Application journals, recordings, archive catalogs, consensus state and snapshots stay on the original overlay-backed state directory.

Use the same existing prepaid host and disjoint four-CPU sets. Three actual UDP replica JVMs plus one load JVM, G1, 1–2 GiB heaps, four active processors, leader 0, MTU 1248, SHARED driver, exact capacity-190k-v1/outbox524288, explicit 1 ms replica maximum park, and the same bounded IOC/256-warmup fixture are fixed. Load samples stay in bounded memory until the window ends, exactly as in the corrected path probe. No comparison against the different R3 durable source recorder or 128-producer cache population is claimed.

A uses the existing overlay-backed media-driver directories. B selects an exclusive experiment-owned `/dev/shm/vectormatch-probe-*` root for replica, load and post-window observer media drivers. The diagnostic helper rejects non-tmpfs roots, relative paths, generic shared paths, symlinks and existing role directories. Production startup defaults remain unchanged. Capture actual `/proc/PID/maps` backing paths for every owned JVM and startup filesystem attestation. Archive raw evidence and durable state before removing only the exact owned empty tmpfs root after JVM closure.

Use one qualified artifact for two functional 10/s, 2-second MATCHING runs (A and B), then four 60-second, 100/s runs in A1/B1/A2/B2 order. Only communication-buffer placement changes. Every original source frame, response, planned/released/offered/confirmed timestamp, service callback, GC/JFR, process metrics, final canonical state and independent wire/sequence arithmetic audit is retained. No raw arm is retried under the same candidate. Safety/correctness/identity failure stops; performance failure remains archived and the precommitted four finite arms may finish.

Promote B only if both B arms accept every original with zero unknown/rejection/not-sent, source release lateness at most 20 ms, at least 99% confirmations inside the window, p99 at least 10% lower than paired A and p99.9 no higher. Report CPU and file-force costs. If both pairs pass, run B for one uninterrupted 1800-second, 100/s window and apply the path-probe long gates (all originals accepted, release max ≤20 ms, global and every minute p99 ≤25 ms, global p99.9 ≤100 ms, correct final state). Otherwise preserve the negative result and do not repeat a baseline long run: the preceding path-probe campaign already measures it.

This is same-host, bounded-state evidence. It does not establish independent physical failure domains, power-loss durability, continuous outbox export, 100K/s capacity or hard realtime. No new paid cloud resources are authorized or needed for this experiment.
