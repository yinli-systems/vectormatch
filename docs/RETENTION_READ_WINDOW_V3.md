# Experimental V3 bounded maintenance read windows

This candidate adds an exclusive, single-owner maintenance read bank with selected window **1 or 8**. Both arms use the same new API and artifact, business batch cap 4, archive chunks 6144 bytes, event fetch pages 16, W128/Q64, one physical client session, and the same finite profile. Default constructors retain window 1. The V2 implementation and wire/reply formats are unchanged. This is a functional prototype; it does not prove independent-host capacity, production durability, or 100M endurance.

## Credit and failure contract

A phase reserves at most the selected number of reads without arming them. The coordinator records and flushes all original request wires before arming any slot. Each slot retains its immutable correlation, bytes and absolute deadline. Reserved, armed and completed-but-unconsumed slots all consume credit; a successful callback stops retries, and explicit consume after reply/timing flush releases credit exactly once.

Only `ArchiveChunk` or `FetchEvents` may use a bank, and each generation permanently selects one kind. `PrepareArchive`, `ArchiveCommit` and `EventAck` remain serial. No business/control request may overlap a read phase. The archive bank stays open through exact canonical verification and writer force/readback; the event bank stays open through exact event verification and force/readback. Both close before either destructive ACK. Future scheduled arrivals continue during maintenance, while business dispatch pauses.

The original deadline and existing maximum 4 possible offers apply to every read. A definite negative offer rolls back its possible-execution reservation; throwing offers remain possibly executed. A first read error, bad binding, deadline or evidence failure stops the bank before additional sibling offers. Exceptions retain every currently retained original (at most8) and its admission/completion observations even if failure-artifact writes fail. Completed and consumed reads remain in the authoritative raw tapes. Unknown outcomes never authorize ACK, fresh-key reissue or credit recycling.

Correlations are globally monotonic and never reused. Live lookup precedes a bounded256-entry retirement ring; old correlations at or below the allocated high-water mark cannot complete a new read after ring eviction. A future correlation or invalid scope/binding fails explicitly. Existing physical callback recording and actual Aeron Image/Header geometry checks still run for every callback, including duplicates.

## Bounded evidence and metadata

The physical raw registry retains its hard cap 129, with explicit business/control-versus-read phase exclusion. Read reservations, armed unresolved reads and positively offered awaiting-callback reads have separate high-water counters. Reservation high water alone is not proof of actual offered overlap.

`logical-rpc-timings.csv` has13 columns: `rpc,kind,correlation_id,start_monotonic_ns,end_monotonic_ns,elapsed_ns,completed,archive_chunk_requested_bytes,event_fetch_requested_count,read_phase_generation,read_window,armed_monotonic_ns,owner_reply_completed_ns`. Serial controls use phase/window0 and empty arm/callback timestamps. Read rows carry real phase, selected window and owner timestamps. End precedes timing flush/consume, so it is not an exact retained-credit release timestamp. Per-RPC elapsed intervals may overlap; their sum is not maintenance wall time. Correlate by immutable correlation, not global request/reply position.

Both selected windows share the complete max 8 staging/failure envelope. No raw 2 GiB, allocated-growth 2.5 GiB, writer 1 GiB, file, journal, retry or free-space ceiling is widened. Actual6400-arrival common plans admit and differ only in `requestedReadWindow`; the full-hash prospective 350k plan with the current retry allowance exceeds the unchanged growth ceiling and is rejected. A future larger experiment needs a separately reviewed finite admission, not a weakened gate. Conservative codec upper bounds are distinct from a workload-shaped encoded witness and from an observed network reply.
