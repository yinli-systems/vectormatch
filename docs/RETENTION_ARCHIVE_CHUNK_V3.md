# Bounded archive read chunk experiment

This candidate starts from4102446 and changes only the requested ArchiveChunk size in the comparison:3072 or6144 bytes. Both arms use this same new artifact, the same finite profile, business frame cap4, W128/taskQ64/internal pending128, one session/shared driver, event page16,3072-command maintenance cuts,50us flush, original wait strategies, appointed leader0, sync2 and MTU1248. Default requested chunk remains3072 and existing pilot API remains callable. This is separate from the historical batch1/batch4 cohort.

The new codec supports chunks up to6144 with unchanged tags/layout and complete8192-byte reply cap. Old legal3072-byte requests/replies retain their wire bytes. The accepted V3 chunk range intentionally expands; an old V3 peer cannot decode new6KiB traffic. Strict actual code/profile identity prevents mixed versions. Legacy V2 is unchanged. Unsupported comparison factors (including3073/6145), oversized codec payloads and transport requests above the selected chunk policy fail before publication. Short final chunks remain legal.

The full attainable Chunk reply bound is775+data bytes: magic/version6, maximum scope136, correlation8, seven counters56, maximum state hash68, maximum error132, payload tag1, ACK five68-byte strings plus two8-byte integers356, and total/offset/count12. At6144, the application envelope is6919 bytes and the Aeron cluster session header adds32, totaling6951. Request envelope is519 bytes including its ACK and all fields. Neither payload-only reasoning nor the8192 reply cap alone proves transport fit. ActualAeron1.53.3 FrameDescriptor uses min(term/8,16MiB); even a64KiB term has8192 maxMessage. MTU remains1248, so larger replies can increase UDP fragment count and recovery cost.

Before the owner admits business, the transport records actual egress subscription Images with correlation/session/stream identity, actual term length and MTU, then derives maxMessage from those observations. Both arms require the same6919-byte application bound, with32-byte cluster header. A bounded ever-seen inventory (at most16 identities/256 lifecycle events) records actual Image additions/removals and retains retired identities/counters. Metadata for an existing identity is immutable; an empty live set, unsupported geometry, a retired identity returning or exhausted inventory fails. Defaults are never substituted. Each reassembled reply Header must bind to its actual live Image and admitted subscription. An unfamiliar/inactive Header triggers an actual subscription resample before association; normal replies use the already validated identity without allocating a new collection. Initial,1Hz and final owner observations plus total reply-header associations are retained. Final functional proof requires every recorded reply to have an actual header/Image association.

Plan computes both complete codec/RPC inventories, then uses their common maximum for raw/allocated/free-space/writer/RPC/physical retry/negative-offer limits. Selected expected chunk/RPC counts are separate metadata. A common2MiB reserve explicitly includes the new bounded egress sample/terminal metadata. Every hard cap is identical across the two arms; larger reply retry costs are included, not assumed to decrease with RPC count. Admission may fail and never authorizes raising a hard ceiling. Canonical archive/event payload bytes, writer force/readback, ACK identities/caps and event page16 remain unchanged.

Logical RPC timing CSV additionally records actual requested archive bytes and event page count. Binary request/reply tapes remain the authority for original identities and received bytes. Each maintenance cycle records selected chunk policy. No malformed/reordered/truncated data is ACKed: the existing exact descriptor/offset/hash-chain/canonical verification and durable readback precede both destructive ACKs. Lost ACK responses retain original identities and UNKNOWN semantics.

The local functional comparison is two fresh6400-arrival/500-per-second/12.8-second runs at fixed business cap4, each crossing three cuts. It is not ABAB, multi-host throughput, a p99 SLA, sustained capacity, or a100M proof. All failures and timing-invalid runs are preserved. A later CPU ABAB requires a separate registration and same-runtime configuration validation. No outbox Fetch removal, asynchronous maintenance, force reduction or journal-retention change is part of this experiment.

Explicit paired runner: `RetentionCapacityAeronPilotV3 <fresh-pair-root> archive-chunks <fixed-port-base>`. The fixed port base must be canonical; all15 UDP ports are checked before pair creation/registration, and an occupied port fails without fallback. The original one-argument pilot API remains available.
